Introductory notes

These pages serve three-dimensional maps of interstellar dust reddening as a function of angular position and distance. The maps combine photometry of hundreds of millions of stars with stellar parallaxes, and are described in the papers linked from the papers page.

Two interfaces are available: the interactive query page for single lines of sight, and the Query API for programmatic access to many coordinates at once. The Python package dustmaps wraps both the API and the local data files in a single interface, and is the recommended way to use the maps.

Versions

Each release of the 3D map has its own name, listed in the table of served maps below. Older versions remain available so that published results can be reproduced; new work should normally use the latest release (bayestar2019 for the all-sky map, decaps for the southern Galactic plane, edenhofer2023 for the local 1.25 kpc).

Units

The maps do not all report the same quantity, and the Bayestar maps do not report E(B−V) directly. Bayestar values are in the same normalization as the original SFD map (Schlegel et al. 1998): one unit of Bayestar19 or Bayestar17 reddening predicts the same E(g−r) as one unit of SFD.

Table 1 of Green et al. (2019) gives the extinction coefficients per unit of map value:

grizyJHKs
3.5182.6171.9711.549 1.2630.79270.46900.3026

Therefore E(g−r) = (3.518 − 2.617) × value = 0.901 × value, and using the RV = 3.1 Fitzpatrick (1999) relation E(B−V) = 0.981 E(g−r) from Table 6 of Schlafly & Finkbeiner (2011), E(B−V) ≈ 0.883 × value.

The interactive page plots E(g−r) for the Bayestar maps, which is the convention this site has used since 2015, and applies the 0.901 factor. The JSON API always returns the raw map values, so apply the conversion yourself if you need a different quantity. Bayestar15 uses the extinction law of Fitzpatrick (1999) and Cardelli et al. (1989) and is normalized to SFD itself, so its coefficients (and the exact E(g−r) factor) differ slightly from the values above.

DECaPS reports E(B−V) in magnitudes directly (no conversion needed); assume R(V) = 3.32 for A(V). Edenhofer et al. (2023) reports integrated extinction in the units of Zhang, Green & Rix (2023), labeled E (ZGR23) in the API. The interactive page plots E(440 nm − 550 nm) for this map, applying E(440 nm − 550 nm) = 0.9664 × E from the extinction curve published with the map (Zenodo 7811871).

Samples

The probabilistic maps (Bayestar, DECaPS and Edenhofer 2023) return a posterior distribution in each pixel, and the query modes select how it is summarized: best (maximum-posterior profile), median, mean, percentile, std, random_sample, random_sample_per_pix, and samples (the stored samples themselves: {{ max_samples }} of them for Bayestar and DECaPS, and all 12 for Edenhofer 2023). Which modes a map supports is in its entry in /api/v2/maps.

Quality assurance

Bayestar and DECaPS return flags with each query: whether the line-of-sight fit converged, and the range of distance moduli over which the reddening is reliable (min_reliable_distmod, max_reliable_distmod). Outside that range the map is extrapolated. Request these with return_flags=True; the interactive page hatches those distances and labels them "unreliable". Edenhofer et al. (2023) does not provide these flags.

Deprecations

The original endpoints /gal-lb-query and /gal-lb-query-light still work but are deprecated and return a Deprecation header. They are superseded by /api/v2/<map>/query; please migrate, since the old endpoints will be removed once traffic falls to zero.

Query API

Prefer the Python dustmaps package. It handles the JSON encoding, the coordinate frames and each map's options for you, and its *WebQuery classes (dustmaps.bayestar.BayestarWebQuery, for example) call this endpoint. Use the HTTP interface directly only where dustmaps cannot run.

POST /api/v2/<map>/query accepts a JSON body with coordinates (l, b), (ra, dec, optional frame), or a dustmaps-serialized coords object, plus an optional distance d in kpc and map-specific keyword arguments such as mode, pct and return_flags. Arrays are base64 encoded, exactly as produced by dustmaps.json_serializers.

Limits

Requests are rate limited per client, counted both as requests and as work units (coordinates × samples × distance bins). The response headers X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset report your budget, and a 429 response includes Retry-After. Ask for many coordinates per request, and only the modes you need, to stay well inside the limits.
