Privacy

Short version: we keep anonymous aggregate counts, not visitors.

What is stored

For each successful query we increment a counter. Each counter records only: the UTC date, the map queried, the endpoint, the country, and the one-degree grid cell of the resolved client location, together with the number of queries, number of coordinates and total processing time.

We do not store IP addresses, user agents, cookies, session identifiers, per-request records, or exact timestamps. There are no third-party analytics, advertising or tracking scripts on this site, and every asset (fonts, styles, JavaScript) is served from this domain.

Why we collect it

Aggregate counts tell us which maps the community relies on and whether the service needs more capacity. This is our legitimate interest in operating and funding the service. Rate limiting exists to keep the service responsive for everyone.

IP addresses and rate limiting

IP addresses are personal data under the GDPR, so we handle them conservatively. During a request the address is used in memory to count the request against a budget and, if a geo database is installed, to resolve a country and coarse location. The counter key is a keyed hash (HMAC-SHA256) of the address prefix, using a salt that is rotated daily; IPv6 addresses are grouped by /64. Counters expire after the rate-limit window and are purged, and the salt is discarded after the day ends, so stored hashes cannot be linked across days or back to an address.

Retention

Aggregate rows are kept for {{ retention_days }} days and then deleted. Rate-limit counters are kept only for the length of their window. Server logs contain request IDs, endpoints, map names, counts and timings — never IP addresses.

Your rights

Because we do not hold personal data beyond short-lived pseudonymous rate-limit counters, there is normally nothing to access, correct or erase. If you believe a request of yours was mishandled, contact the site maintainer and quote the request ID shown in the response headers.
